# Vendored Jekyll shell provenance

The candidate shell is a flattened historical website shell, not a proven `@*/core` package. `scripts/source-shell-provenance.json` records the family-specific historical repository, commit, shell SHA-256, legacy npm package and lockfile integrity. `nightjar/PROVENANCE.json` records the workbench source export and Git blob for every file.

The family website commit's `site/src/styles/shell.css` imports the recorded `@*/theme/css` and `@*/theme/foundation.css`; its origin styles also import `@*/theme/legacy.css`. Its `package-lock.json` pins the exact legacy package and integrity in the JSON file. A local clean source export of that commit, the historical `scripts/generate-shell.mjs`, and the installed legacy package produced exactly the recorded vendored shell SHA-256. The installed package files were individually compared with a separately downloaded registry tarball: 42 Martlet files and 46 Krigsvold files matched, and each tarball's SHA-512 matched the historical lockfile. These findings identify the legacy dependency and reproduced composite CSS, not an npm Core version or an authenticated immutable source of future releases.

`scripts/docs-archive.py` builds the complete Jekyll reference from its explicit source manifest, including the 50 recipes, assets and source ZIP, for a specified framework version. It reserves each local version once, sets `noindex`, writes per-file hashes and historical shell provenance, and renders an accessible static list of the current and explicitly supplied earlier versions. It supports root and subpath builds. The list in an old immutable snapshot cannot discover newer versions without a separately designed trusted catalog; the candidate does not pretend otherwise.

The local output and its evidence file are a prototype and do not satisfy the shared production archive contract: Core is intentionally null because this shell uses legacy `/theme`, remote archive immutability and catalog authentication are not implemented, and there is no stable deployed URL or automatic latest pointer. The explicit documentation publication gate remains in force.
