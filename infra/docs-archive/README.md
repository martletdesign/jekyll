# Jekyll archive gateway experiment

This isolated, nondeploying experiment adapts the archive-object portion of the Astro R2 gateway at `martletdesign/astro` draft #11 (`727a8fa`). It validates a Jekyll Git implementation identity and the actual legacy `@*/theme` dependency and shell digest. The manifest sets `core` to null: it does not claim that the old flattened shell uses `@*/core`. This experimental manifest deliberately differs from the current shared documentation contract and must not be treated as production interoperability.

The `docs-r2` test builds the actual complete local Jekyll reference at root and `/preview`, sends every file through the adapted Worker against a conditional-write in-memory R2 double, commits a digest-checked manifest, reads and checks every file, and checks authorization, overwrite rejection, wrong Core identity and corrupt-byte failure. It uses the current checkout SHA only as a local test source identity. A second locked test (`npm ci --prefix infra/docs-archive --ignore-scripts` then `node infra/docs-archive/smoke.mjs`) sends all actual snapshot files through Miniflare's local Workers and R2 emulator under `/preview`, checking bytes and overwrite rejection. Neither test publishes or deploys anything, and the prerelease `VERSION` is a test sentinel, not a published tag.

Catalog, promotion and latest endpoints deliberately return 503 because the shared contract cannot represent this legacy dependency. The existing release documentation gate remains unconditionally closed. Before production use, define and review a common compatible manifest contract, independently trust source/tag and legacy dependency evidence, configure separate and limited bucket authority, test the actual R2 runtime and concurrent/error recovery, provide a tamper-resistant off-bucket history checkpoint, stable serving, and verify retention/rollback. R2 conditional writes and this Worker do not prevent privileged bucket changes or deletions. A mutable pointer in the same bucket is not an independent trust anchor. No Cloudflare resources, secrets, deployments, releases or publication are changed by this draft.
