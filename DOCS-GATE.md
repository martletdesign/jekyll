# Jekyll documentation release gate

The source-release proposal must not produce a GitHub Release until the exact Jekyll version's documentation is built, archived and independently verified in immutable remote storage. `scripts/verify_docs.py` intentionally fails in both release jobs. It must be replaced by a reviewed implementation that authenticates stored archive and catalog history, verifies complete bytes and exact core dependency integrity, prevents overwrites, and proves stable historical URLs before activation.

`scripts/docs-versions/{contract,snapshot}.mjs` are copied from the historical-theme extension in workbench draft #77, based on `658698c6b5b0469a04f1722819f20320277421f8`. Their local test uses synthetic Jekyll/Core identities and a fake integrity value to check both languages, successive snapshot preservation, core-lock mismatch, overwrites and tampering. It exercises the shared contract only. It does not demonstrate a Jekyll documentation build, prove that the existing vendored shell derives from the synthetic Core version, provide remote immutability, or establish live URL serving. Determine and verify the real source-shell/Core provenance before recording any exact Core dependency.

The local prototype builds the 50 canonical examples with static navigation and noindex. Older snapshots cannot discover later versions. Authenticated catalog updates, canonical URL policy, immutable storage, protected pointer updates, stable serving and recovery remain unimplemented. Preserve the explicit fail-closed gate until those gaps are closed.
